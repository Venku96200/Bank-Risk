# Banking Transaction Risk Monitor

FastAPI MVP demonstrating deterministic rules, Isolation Forest anomaly detection, hybrid scoring, analyst workflow, and a local RAG explanation layer.

## Setup

1. Create PostgreSQL database `banking_risk`; copy `.env.example` to `.env` and set `DATABASE_URL` (or export it).
2. `pip install -r requirements.txt`
3. Either generate the included demo data with `python data/generate_data.py` and `python ml/train.py`, or train unsupervised on the supplied bank dataset:

   `python ml/train.py --source "C:\\Users\\mahan\\Downloads\\bank_fraud.csv" --sample-size 100000`
4. `uvicorn app.main:app --reload`
5. Open `http://127.0.0.1:8000`.

## Architecture

Transactions are assessed by transparent rules (amount, device, location, hour, velocity) and Isolation Forest. The bank-fraud training option deliberately ignores `is_fraud` and `fraud_type`; it uses transaction behaviour only. `0.6 * rule + 0.4 * ML` determines the 0–100 score and HIGH/CRITICAL alerts. At startup, `rag_explainer.py` embeds synthetic policy documents using MiniLM, indexes vectors in FAISS, retrieves the nearest policy text for alert reasons, and renders a citation-rich template explanation.

## Phases delivered

1. SQLAlchemy schema, FastAPI skeleton, health endpoint.
2. Reproducible 6,000-row synthetic generator.
3. Rule engine and core tests.
4. Scikit-learn training script and hybrid scoring.
5. Transaction ingestion, bulk CSV, alerts and review workflow.
6. Local embeddings/FAISS RAG plus `/alerts/{id}/explain`.
7. Chart.js dashboard with a distinct retrieved-policy panel.
8. This setup guide and limitations.

## Limitations

All transactions and policies are synthetic; this is not an AML/fraud production system. Customer baselines are deliberately simple, model retraining is manual, and explanations are template-composed from retrieved text rather than generated by a fine-tuned model. A local Ollama model could later improve prose, but is intentionally not required.
